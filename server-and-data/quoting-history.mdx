## What it's for

Business questions rather than fixes: which states clients come from, which business classes TNI quotes, what fleets look like, which coverages and limits clients ask for and which are chosen on each carrier, who insured them before, how it all moves over time, and later, what the carriers quoted.

| Table | One row per |
| --- | --- |
| `events` | Event, once per id, as stored |
| `quotes` / `v_quotes` | Quote; the view leaves out test runs. **Start here.** |
| `quote_vehicles`, `quote_drivers`, `quote_prior_insurance` | Unit or policy on the profile |
| `quote_carriers` | Quote and carrier it was worked on; `outcome` is `done`, `declined` or `stopped` |
| `quote_premiums` / `v_quote_premium` | Each premium reading; the view keeps the last per quote and carrier |
| `answers` | Question and unit a quote answered on a carrier; `answered_by` and `rule_source` |
| `build_info` | The run that built the file |

Column notes live in `TABLES` in [`warehouse.mjs`](https://github.com/lutfikeskin/tni-rater-autofill/blob/main/scripts/lib/warehouse.mjs) and in the file itself:

```sql
SELECT column_name, comment FROM duckdb_columns() WHERE table_name = 'quotes';
```

## Build and query

```bash
npm run pull
npm run warehouse
duckdb -readonly server-data/warehouse.duckdb
```

It refuses to run without a test-run list (`reviews/test-intakes.txt`, or `--tests <file>`), so the maintainer's test quotes never count as clients. Install the DuckDB command line with `winget install DuckDB.cli`, at the same version as `@duckdb/node-api` (1.5.6) or newer.

Where clients come from, by month. `intakes` counts distinct PDFs, so a client re-quoted from the same PDF counts once:

```sql
SELECT date_trunc('month', started_at)::date AS month,
       coalesce(state, '(none)') AS state,
       count(*) AS quotes,
       count(DISTINCT intake_id) AS intakes
FROM v_quotes
GROUP BY 1, 2
ORDER BY 1, 3 DESC;
```

The repository's document has more examples: business classes, the fleet, drivers, a renewal calendar by prior insurer, and coverage chosen per carrier split by who chose it. `test/warehouse.test.mjs` runs every one of them, so a renamed column fails the tests.

## Limits

- **Only quotes run through the extension.** Hand-typed quotes, other carriers and renewals done elsewhere never reach it.
- **No ZIPs, names, VINs or numbers**, by design. State is the finest geography. That's not anonymity.
- **The intake's word, not the policy's.** A limit changed later on the carrier's page shows in `answers`, not the profile.
- **No bind data.** "Done" means the quote reached the final page or was printed.
- **A quote is a panel session, not a client.** The same PDF keeps its `intake_id`.
- **Premiums are quoted, never bound**, and GEICO's numbers are provisional until checked against real quotes.
