TNI Rater Autofill reads a client's **TNI Commercial Insurance Quote Application**, a fillable PDF, and fills the Progressive, AmWINS and GEICO quote pages from it. It runs as a Chrome extension (Manifest V3) with a side panel next to the carrier's page.

The goal is a **correct quote that reflects what the client asked for**, with every decision the extension can't make shown to the agent. A filled field, or a value the carrier accepted, doesn't prove the answer is right.

## The whole picture

<div className="pele-diagram">
```text
flowchart TB
  subgraph PANEL["In the side panel"]
    direction LR
    PDF[/"Intake PDF"/] --> READ["Read and clean:<br/>record + warnings"] --> CHECK["Agent checks<br/>the intake"] --> PLAN["Carrier rules build<br/>a fill plan"]
  end
  subgraph TAB["On the carrier page"]
    direction LR
    FILL["Fill engine answers,<br/>waits, reads back"] --> REPORT["Report: filled,<br/>standard, needs you"] --> AGENT(["Agent confirms<br/>and continues"])
  end
  subgraph AROUND["Around the quote"]
    direction LR
    LUNA["Luna AI suggests<br/>unresolved choices"]
    SERVER[("TNI usage server<br/>redacted events")] --> REVIEW["Weekly review,<br/>tested releases"]
  end
  PANEL --> TAB
  TAB -.-> AROUND
```
</div>

1. The agent drops the intake PDF into the side panel. The extension reads its form fields into a **client record** and flags anything ambiguous.
2. The agent fixes or confirms those flags on **Check intake**.
3. On each carrier page, the carrier's **rules** turn the record into a **fill plan**: which question gets which answer, and why.
4. The **fill engine** (`pagekit.js`), injected into the carrier tab, finds each question on the live page, answers it, waits for the page, reads the answer back and looks for follow-up questions.
5. The panel's **report** says what was filled from the intake, what is a TNI standard, and what is left for the agent. Optional AI suggestions cover choice questions the rules leave open.
6. Usage events, with client details redacted, go to TNI's server. A person reviews them each week, and the fixes they approve ship as tested releases.

## What it never does

<Warning>
The extension never binds, buys, submits or signs. It never orders MVR or CLUE reports, and it never types an answer the intake doesn't support unless TNI has set a standard for it. It clicks Continue only when nothing on the page is left for the agent, and only where the carrier's configuration allows it.
</Warning>

## At a glance

| | |
| --- | --- |
| Extension | Chrome MV3, side panel, version 0.9.20, Chrome 140 or newer |
| Language | Plain JavaScript ES modules, no build step, gradual JSDoc type checking |
| Intake reader | PDF.js, vendored in `lib/` (MV3 can't load remote code) |
| AI | OpenAI `gpt-6-luna`, opt-in, with the agent's own key |
| Server | Plain Node, no dependencies, on Railway; JSONL files per day |
| Tests | `node:test` units, Playwright mocks and replays, packaged-extension end to end |
| Source | [lutfikeskin/tni-rater-autofill](https://github.com/lutfikeskin/tni-rater-autofill) (private) |
